# AGENTS.md

Committed home for project-intrinsic agent knowledge. Keep this file short. Add
sharp-edge notes here as they are discovered through real work; delete anything
that stops being true.

Workflow north star: `docs/workflow-north-star.md` (target operating model and
tool-adoption backlog; check it before adding workflow tooling).

## Safety contract (non-negotiable)

- Agents may run local installation, upgrade, and activation commands necessary to complete setup work the user explicitly requests.
  This includes `brew` and `darwin-rebuild`.
- Prefer a visible local terminal when supported.
  Otherwise use the agent's shell tool and report the results.
- Agents may invoke `sudo` for those authorized operations.
  If authentication is required, let the user enter it locally.
  Never request, read, or store the user's password.
- Continue validating setup scripts through `tests/mac_setup_test.sh`, which runs the bootstrap in a sandboxed HOME with a PATH masked to stub executables.
  Do not run `setup/mac.sh` against the real system merely to test it.
- The daily auto-updater (`scripts/dotfiles-autoupdate`) remains authorized to run without an attended request.
  The `dotfiles-sync` launchd agent (`nix/user.nix`) fast-forwards the main checkout to `origin/main` and updates pnpm globals and brew.
  The `dotfiles-autoupdate` launchd daemon (`nix/host.nix`) switches the system to the exact `origin/main` revision the agent fetched, never to the working tree.
  Anything pushed to `main` is live on the machine within about an hour: the agent hands over origin/main hourly, and its heavy steps (pnpm, brew, macOS updates) run daily from 04:00.
  Unpushed or uncommitted work is never applied by the updater; a system that `rebuild` built from such work stays until the push.
  Alarms reach the zsh banner, the agent board and agent sessions through `dotfiles-autoupdate status`.
- Preserve unrelated changes.
  Writes outside this repo require an explicitly requested setup operation or an approved diff.
- Never print, log, or commit secrets, tokens, private keys, `.env` files, or
  generated credentials. SSH keys are per-device and are generated by the human.
- Do not edit `~/.ssh`, keychain, or login items.
- **Whatever reaches `main` is republished to a sanitized public mirror** (`docs/public-mirror.md`).
  Treat anything committed here as publishable: new personal detail needs a rule in `scripts/public-sync`, or the leak gate in the pre-push hook aborts the push.
  The hourly sync agent runs `scripts/public-sync --from-origin` after it fetches, so a push is published within about an hour; run it by hand to publish sooner.
  A failure is a sync alarm, "the public mirror is behind main", and must be fixed.
  Never commit to `~/dotfiles-public` - it is regenerated.

## Architecture rules

- Layer ownership: **Home Manager** owns the CLI baseline and shell; **Homebrew
  (declared in `nix/host.nix`)** owns GUI/macOS-native apps (Ghostty, OrbStack);
  **ecosystem managers** (pnpm, uv) own per-project tooling via devShells.
  Exception: fast-moving agent CLIs that other apps must be able to update
  install outside Nix - `claude` via its native self-updater, `codex` as a
  Homebrew cask (nixpkgs lagged ~11 releases and T3 Code could not update a
  read-only store binary, 2026-10-07).
- One flake, one bootstrap, no phase install scripts. Growth = small reviewed
  commits to the flake, applied with `rebuild`.
- Terminal layering: **Ghostty** is the emulator. **tmux** is for terminal
  training. **Herdr** is the agent cockpit and runs *inside* Ghostty. Herdr is
  not a terminal emulator. Keybindings must not overlap across the three.
- If `HERDR_ENV=1`, never auto-launch tmux wrappers.
- Remote/SSH logins auto-attach to the persistent Herdr session (guarded
  snippet in `nix/user.nix` initContent); tmux is never auto-launched.
- Neovim base is a personal NvChad `v2.5` config (VSCode-familiar; lineage
  credited in `docs/vscode-to-nvim.md`). Never replace it
  with LazyVim, AstroNvim, Typecraft, or Omerxx's Neovim. It lives outside the
  Nix store (plain clone at `~/.config/nvim`) so it stays fast to iterate on.
  Tripwire (2026-07-06): NvChad is effectively single-maintainer; the config
  pins a fork of NvChad `v2.5` (carries the treesitter-main migration - do
  not repoint to upstream NvChad/NvChad) with `nvchad/ui` + `base46` from
  upstream. If `nvchad/ui` breaks on a new Neovim release and sees no fix for
  ~2 months, that is the one condition under which the LazyVim question
  reopens - as a human decision, not an agent one.
- Containers: **OrbStack only.** No Docker Desktop, Colima, Rancher, Podman
  Desktop, or Lima.
- Toolchains off by default (Go, Rust, Java, Android, k8s, Terraform, AWS/GCP/
  Azure, heavy React Native). They are enabled per-project via
  `templates/devshells/` + direnv - never installed globally.
- **Theme: Catppuccin everywhere. Font: JetBrains Mono Nerd Font everywhere.**
  Applies to every themable tool - Ghostty, tmux, starship, fzf, lazygit,
  Neovim, Herdr. The font is installed system-wide via
  `fonts.packages` in `nix/host.nix`. Do not introduce other themes or fonts.
- Omerxx dotfiles: fallback inspiration for tmux/zsh/starship/Ghostty/macOS
  automation only. Never for Neovim.

## Delegation

- Use strong models for architecture, keybinding strategy, security review, and
  final integration review. Use cheaper models/subagents for scanning, summaries,
  config drafting, docs, and formatting. Delegated agents may not touch
  `setup/`, `tests/`, secrets-adjacent files, or `AGENTS.md`.

## How to test

- `bash tests/mac_setup_test.sh` - must pass before proposing bootstrap changes.
- `nix flake check` / `nix build .#darwinConfigurations.<host>.system --dry-run`
  for flake changes (agent may run these; they don't mutate the system).

## Sharp edges (append below as discovered)

- Fresh-macOS bootstrap: the Determinate *curl* installer can fail mid-install
  ("Volume on disk3s7 failed to mount") because the `/nix` firmlink needs a
  reboot to appear. Fix: reboot, install via the native pkg
  (https://dtr.mn/determinate-nix), then re-run `setup/mac.sh` (2026-07-05).
- Determinate Nix runs its own daemon, so nix-darwin must set
  `nix.enable = false` or activation aborts with "Determinate detected".
  `nix.*` options are then unavailable; Nix settings live in
  `/etc/nix/nix.custom.conf` (flakes are on by default in Determinate).
- Karabiner rewrites `karabiner.json` in place (breaks file symlinks) -
  `~/.config/karabiner` is therefore a *directory* symlink into this repo, and
  Karabiner's runtime noise (`automatic_backups/`, `assets/`) is gitignored.
  Its rewrites of the tracked json (key reordering, defaults) are expected.
- `nvim --headless` `print()` emits no newlines between calls - anything
  parsing headless output (term-dojo's keymap dump) must join records with an
  explicit separator in Lua and split on it (2026-07-05).
- Home Manager only puts *Nix profile* dirs on zsh `fpath`, so Homebrew's
  completions (`/opt/homebrew/share/zsh/site-functions`, e.g. `_brew` cask
  names) were invisible until fpath'd via `initContent` at `lib.mkOrder 550`
  (= before oh-my-zsh's compinit). Test completions headlessly with
  `tests/zsh_completion_probe.zsh 'brew install --cask fire'` (2026-07-05).
- Never auto-wrap shells in inshellisense (`is`): its pty re-renderer corrupts
  full-screen TUIs - nvim/lazygit layouts break, mouse escape sequences leak
  as text (microsoft/inshellisense#411). It is installed for opt-in sessions
  only; fzf-tab is the always-on completion layer (2026-07-05).
- `homebrew.onActivation.cleanup = "zap"` uninstalls (and zaps prefs of) any
  brew formula/cask not declared in `nix/host.nix` - a plain `brew install`
  lasts only until the next switch, which runs within about an hour of any
  push to main (the owner kept zap for that, 2026-10-16). Declare everything; adopt
  already-present apps with `brew install --cask --adopt <cask>` (2026-07-06).
- Removing a cask from `nix/host.nix` runs its *zap* stanza, which can trash
  data shared with other installs (claude-code's zap deletes `~/.claude.json*`
  and the native `~/.local/share/claude`). Before dropping a cask, read its
  zap list (`https://formulae.brew.sh/api/cask/<token>.json`); if it touches
  anything still in use, have the human `brew uninstall --cask <token>`
  (no zap) before the next activation (2026-10-07).
- nix-darwin activation runs `brew bundle` *before* Home Manager, and a
  bundle failure aborts the rest. From 2026-08-25 to 2026-10-07 every rebuild
  silently left Home Manager unapplied (stale `~/.zshrc`, links, packages)
  while `/run/current-system` still advanced. Upgrades now run as a separate
  `brew upgrade` after the switch. Check HM actually applied with
  `readlink ~/.zshrc` (store path should change after a rebuild that touches
  `nix/user.nix`) (2026-10-07).
- The axi tools (gh-axi, chrome-devtools-axi, lavish-axi, tasks-axi) are pnpm
  globals in `$PNPM_HOME/bin` (~/Library/pnpm/bin), updated daily by the
  `dotfiles-sync` agent (`pnpm update -g --latest`). Claude Code runs all
  four at session start through one managed hook, `scripts/axi-session-start`,
  which calls the bare command names, so updates do not break it, and cuts
  each list to a count: Lavish's own hook printed 70 sessions into every
  thread (2026-10-16). `merge-settings.sh` removes the tools' own SessionStart
  hooks on each switch; `<tool> setup hooks` adds one back until then.
  Bare `chrome-devtools-axi` and `lavish-axi` resolve to the wrappers in
  `scripts/` (earlier on PATH), which run the pnpm globals (2026-10-10).
- chrome-devtools-axi and agent-device are pinned pnpm globals: the daily
  update skips them and re-asserts the versions in `pins=`
  (scripts/dotfiles-autoupdate). pnpm 12's `update -g --latest` moves exact
  pins too, and a `'!pkg'` filter makes it update nothing, so the sync names
  the floating globals instead.
  axi's server (chrome-devtools-mcp) is pinned in nix/user.nix, and the two
  must match: axi 0.1.30 against server 1.10 (page-ID routing on by default)
  failed every page command with "pageId: Invalid input: expected number,
  received undefined"; axi 0.1.39 fixed it. After bumping either, run
  `chrome-devtools-axi open https://example.com` and `eval document.title`
  against the agent Chrome (2026-10-10).
- Signing in to Google inside a Chrome profile also signs the browser in,
  and Chrome then installs the account's synced extensions there. the owner's
  Gmail sign-in in the agent Chrome pulled in Dashlane, AdBlock, AI sidebars
  and four more; Dashlane's content script broke Greenhouse form fields under
  automation. The agent Chrome therefore launches with `--disable-extensions
  --disable-sync`, and the wrapper refuses it without them. Never uninstall
  extensions in a profile while sync runs: the uninstall syncs to his own
  Chrome (2026-10-10).
- The agent Chrome is one headed window on the owner's main screen, in the same
  spot as his own Chrome and T3 Code, and every agent shares it. `resize`
  reshaped it for all of them (macOS floors it at 500px, so "390" phone
  shots came out 500 wide), and foreground tabs raised it over his windows
  with other agents' emulated tabs in front. He read that as Lavish pages
  "cut off, or showing in a mobile sized view only". `scripts/chrome-devtools-axi`
  now opens agent tabs in the background, refuses `resize` in favour of
  per-tab `emulate --viewport`, and takes `--foreground` for a page he must
  click (2026-10-11).
- Driving plugin-heavy nvim via `tmux send-keys`: key bursts in one call
  (e.g. `send-keys "dd"`) get eaten by the plugin UI (noice/which-key) while
  it settles - send one key per call with ~1s gaps, and allow ~9s for nvim
  startup. Harness pacing only; humans typing normally are unaffected. Also:
  `tmux -t dojo` fuzzy-matches a *window* named dojo over the session - use
  ids (`$N`/`@N`/`%N`) from `#{session_id}` etc. for unambiguous targeting
  (2026-07-05).
- System node and pnpm come from nixpkgs, so a flake bump can move them. On
  2026-10-10 node 22.23.2 -> 22.23.3 and pnpm 11 -> 12 broke job-tracker's
  commit hooks. Every switch now prints `scripts/toolchain-diff` warnings for
  node and pnpm changes; projects should pin their own toolchain (2026-10-10).
- nix-darwin's `services.github-runners` asserts `nix.enable`, which Determinate
  rules out, so job-tracker's self-hosted runner is declared by hand in
  `nix/github-runner.nix`. Creating its `_github-runner` user needs a macOS
  admin prompt: `rebuild` must run in a GUI session, not over SSH (nix-darwin
  aborts there). Registration needs no sudo: `github-runner-register` queues a
  one-hour token the service consumes (2026-10-11).
- pf: never reload the main ruleset (`pfctl -f /etc/pf.conf`); system services
  add anchors to it at runtime. Load a child of the `com.apple` anchor instead
  (`pfctl -a com.apple/<name> -f`), which Apple's pf.conf already evaluates.
  pf on macOS never sees traffic to this Mac's own loopback or LAN addresses:
  a rule `on lo0` matched 0 packets even with no user condition, so per-user
  loopback isolation cannot be done with pf (the runner's check only warns).
  This Mac's tailnet address routes via Tailscale's utun, which pf does
  filter (2026-10-11).
- The login keychain answers only inside the owner's GUI session. A launchd
  daemon that runs `sudo -u myuser git fetch` has the right user but the wrong
  security session: osxkeychain gets -25308 and git fails with "could not read
  Username for 'https://github.com': Device not configured". That broke every
  run of the old root auto-updater (7-10 Oct). Anything that needs the owner's
  git, gh or keychain credentials unattended must be a launchd *agent*
  (`launchd.agents` in `nix/user.nix`), and only the root step goes in a
  daemon. SSH is no way around it: the key has a passphrase, and only the GUI
  ssh-agent holds it (2026-10-11).
- Hooks in a linked worktree get `GIT_DIR`, so anything a hook runs against another repo must first clear `git rev-parse --local-env-vars`.
  Mirror commands of an earlier version of the pre-push hook set `core.bare=true` in `~/dotfiles` (2026-10-16).
