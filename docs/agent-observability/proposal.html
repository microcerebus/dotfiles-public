Verdict

No to agenttrail. Its Kitchen view is carefully built, stays local, and passed every safety check I ran. It answers a different question, though: what roles and todos exist inside one repo, drawn as a 3D cooking game. It cannot tell you which T3 threads are running, which are waiting on you, or how full their context is.

The Map view is worse for us. It runs one daemon per repo and needs a PLAN.md convention. Any web page you visit can trigger its setup endpoint, which edits CLAUDE.md and AGENTS.md and installs hooks.

What it is

  • One script. scripts/agent-board, Node 22 from the flake, no npm packages. It uses node:sqlite and node:http.
  • Read-only. It opens T3's statev2.sqlite read-only and selects explicit columns, never the webhook token or secret. It tails Claude logs only to get the last activity time, or context size when T3 has none. It writes nothing anywhere.
  • Runs as a launchd agent declared in nix/user.nix, next to the agent Chrome. It starts at login and restarts if it dies. It is live after your next rebuild.
  • Network. It listens on 127.0.0.1 and the Tailscale 100.x address only, never all interfaces. It answers GET only and accepts only the MagicDNS and loopback Host names.
  • Hooks and settings: none.
  • Pinning: there's no third-party code to pin. It moves with the flake's Node, and the daily updater stays as it is.
  • Cost: it renders on request, so idle CPU is about zero, with tens of MB of memory and no disk writes. I'll measure the real numbers before reporting done.
How the data flows

Risks

  • T3's database schema is internal and can change on any T3 update. The board shows a plain "schema changed" error instead of wrong data, and a fixture test pins the queries.
  • Every device on the tailnet can read thread titles and branches. That means only your devices, which I'll confirm before it goes live.
  • Usage windows stay out until there's a real local source. Only the CLI statusline gets them, and T3 sessions don't run it.

Done means

  • A fixture test (node --test) passes with a sample database and log.
  • A phone-viewport screenshot of the live MagicDNS page shows real running threads. It stays local, because it contains thread titles.
  • Measured CPU and memory over 10 minutes.
  • Committed the same day. Only you run rebuild, and I push only after you say "push".

Audit record

  • Versions. agenttrail-kitchen@0.1.0-alpha.3 and agenttrail@0.2.0. Both npm tarballs match registry integrity. Source read at commit e4ba2da.
  • Project health. MIT license, one maintainer, last commit 9 Sep 2026, 6 open issues. Kitchen is labeled experimental.
  • Network. It only talks to its own ports on 127.0.0.1. No telemetry, CDN or update check, and the page's CSP limits it to connect-src 'self'. While it ran, it held no sockets except its listener.
  • Bundle. I rebuilt Kitchen's 680 KB app.js from the pinned source and lockfile, and it came out byte-identical, fonts included.
  • Ports. Kitchen uses 4780 and up, Map 5330 and up, both bound to 127.0.0.1 with no flag to change it. Kitchen also rejects requests whose Host isn't 127.0.0.1 or localhost.
  • Reads. Every 5 seconds it reads the first 64 KB of up to 240 logs changed in the last day, under ~/.claude/projects and ~/.codex/sessions. Full event bodies, the last 2 MiB, only for watched folders. It skips subagent logs.
  • Writes. Kitchen writes ~/.agent-office/ (mode 0600), plus repo hooks only through "Connect agents". Map writes ~/.agenttrail/, and its init writes PLAN.md, CLAUDE.md, AGENTS.md, .gitignore and hooks.
  • Browser. Both call macOS open, which means the default browser, unless given --no-open. The trial used --no-open and a logging stub for open, which was never called. I viewed it only in the agent Chrome.
  • Security. Kitchen checks Host and Origin, needs a token for every POST, and sends only allowlisted fields. Map checks nothing: POST /setup and /spawn accept requests from any web page.
  • Cost. With 57 sessions watched: about 2% CPU on average, 108 MB of memory, and a 940 KB package.
  • Footprint. State lived in /tmp. Nothing was left in my home folder or any repo, and no hooks or settings changed.
