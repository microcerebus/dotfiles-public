| System switches take the auto-update's switch lock (`~/dotfiles/AGENTS.md`) | `bash_guard.py` blocks `darwin-rebuild` `switch`, `activate`, `--rollback` and `-G`/`--switch-generation` at command position: after `;`, `&&`, `|`, newlines and backslash-newline continuations, after the reserved words `if`, `then`, `elif`, `else`, `do`, `while`, `until`, `!` and `{`, behind `sudo` (with its flags), `env`, `exec`, `command`, `nice`, `nohup`, `time`, `timeout` and `caffeinate`, through `nix [flags] run` of the nix-darwin flake or any `#darwin-rebuild` installable named before `--`, and inside `sh`/`bash`/`zsh -c` strings. Its message names only the `rebuild` and `rollback` aliases. Read-only `build`, `check`, `--list-generations` and `changelog` pass, as do mentions in quotes, comments, heredoc bodies, commit messages and greps, and `nix run` of another flake with nix-darwin among the program's arguments after `--`. A quoted or escaped heredoc delimiter may start with any character (`<<'-EOF'`, `<<\1`); a bare one starts with a letter, and a `<<` after an unclosed `((` or `$((` on the same line is a shift, so `x=$((1<<n))` opens no heredoc that would hide the lines after it. A heredoc body ends on the first line that equals its delimiter once both are stripped, never later than the shell ends it, so a spaced `<<' EOF'` hides no command after the body. Arithmetic opened on an earlier line is not tracked, so a `<<` inside it can still be read as a heredoc start. It is a guardrail, not a sandbox: `eval`, `xargs`, `nix shell -c`, `$(command -v darwin-rebuild)`, `function f { ...; }` and running `activate` directly still pass; `tests/claude_hooks_test.sh` covers each case, and `tests/autoupdate_test.sh` cases 31 and 32 check that both aliases wait for the lock |
