| System switches take the auto-update's switch lock (`~/dotfiles/AGENTS.md`) | `bash_guard.py` blocks `darwin-rebuild` `switch`, `activate`, `--rollback` and `-G`/`--switch-generation` at command position: after `;`, `&&`, `|`, newlines and backslash-newline continuations, after the reserved words `if`, `then`, `elif`, `else`, `do`, `while`, `until`, `!` and `{`, behind `name=`, `name+=` and `name[i]=` assignments, `sudo` (with its flags), `env`, `exec`, `command`, `nice`, `nohup`, `time`, `timeout` and `caffeinate`, through `nix [flags] run` of the nix-darwin flake or any `#darwin-rebuild` installable named before `--`, and inside `sh`/`bash`/`zsh -c` strings. Its message names only the `rebuild` and `rollback` aliases. Read-only `build`, `check`, `--list-generations` and `changelog` pass, as do mentions in quotes, comments, heredoc bodies, commit messages and greps, and `nix run` of another flake with nix-darwin among the program's arguments after `--`. The guard reads each command three times, as zsh, bash 5 and bash 3.2 would, and blocks if any reading does. It reads a heredoc delimiter with the shell's quote removal, so `<<E"OF"`, `<<\E\OF` and a word split by backslash-newline all wait for `EOF`, and it ends the body on the first line equal to the delimiter, as all three shells do: after `<<-` also once the line's leading tabs are dropped, and with backslash-newline lines joined first after an unquoted delimiter, inside backticks, and for bash 3.2 inside `$( )`. An indented `EOF` line is body text, so an apostrophe after it cannot hide the command after the real end. Inside `$( )` and `<( )` the bash reading also ends a body at a line that starts with the delimiter and holds a `)` later, as bash does. The bash 3.2 reading finds the `)` that closes a `$( )` as bash 3.2 does before it reads any heredoc: it skips quotes, `$'...'`, backticks, escaped characters, `#` comments after a blank and a double-quoted `${ }` with the quotes inside it, and a quote or paren left open in a body stays open after the body ends. Inside backticks both bash readings end a body at the first unescaped backtick. A heredoc opened inside a `$( )` that spans lines is read before one opened earlier outside it; one whose `$( )` closes on its own line has no body for zsh and bash 3.2 and is read first by bash 5, and one inside backticks that close on its line has no body. A `<<` after an unclosed `((`, `$((` or `$[` on the same line is a shift (`x=$((1<<n))`), and so is one in bash after an unclosed `name[` that starts the command word (`a[1<<2]=3`), also after `time`, `time -p`, `time -p --` and, in bash 5, `coproc`; zsh, and bash anywhere else (`echo x[ <<EOF`), read a heredoc there. The guard blocks a `name[` it cannot place: one after other words that hold a quote, `$`, a backtick, a backslash, a brace, a bracket, `)`, a redirection or `#`, or after `coproc` and another word, which bash 5 still reads as an assignment. Inside `${ }` a `<<` is pattern text (`${x#<<}`). Commands inside `$( )`, `<( )`, `>( )` and backticks count, quoted or not, also inside `"${x:-$( )}"`, and a `#` comment inside backticks ends at the closing backtick, as the shell cuts out the backtick text before it reads it; the rest of a `"${ }"` is text, and zsh reads `'` and `$'` inside it as literal characters. In the zsh and bash readings a `case` pattern's `)` closes no `$( )` when the guard finds the `case` at command position (after `;`, `&`, `|`, `(`, a newline or reserved words, within about 64 characters of the last of them); the bash 3.2 reading closes it there, as bash 3.2 does. The em dash and handoff checks also read the text inside the `$( )`, `${ }` and backticks of a commit message or an echo line. `$'...'` ends at its first unescaped quote, and a lone trailing backslash is a literal. The guard blocks a call it cannot read: a heredoc delimiter word with `$'`, `$"`, `${`, `$(`, a backtick or an unclosed quote in it, bash 5.3's `${ cmd; }`, nested backticks or a backslash before a backtick, `\` or `$` inside backticks, a backslash in a `#` comment inside backticks, a reading shlex cannot split, more than 32 passes over unclosed quotes, a command that needs more than the guard's work budget (3 million characters scanned, about 2 s of CPU on Python 3.9), or an error in the guard itself. A quote left open at the end of a command is read as a literal, so the guard can block a command the shell would reject. Gaps it leaves open: `$( )` and backticks inside an unquoted heredoc body run but are read as body text; arithmetic opened on an earlier line is not tracked, so a `<<` inside it can still be read as a heredoc start; a newline inside `((`, `$[` or a bash `a[` subscript while a heredoc is pending makes the guard read the next line as the body, where bash reads the body only after the arithmetic closes; a `case` after `time -p`, or more than about 64 characters after the last separator, is not seen at command position, so its pattern `)` closes a `$( )` in the guard's zsh and bash readings; joining backslash-newline lines in a heredoc body is not charged to the work budget, so an unquoted body of `x\` lines takes about 3.4 s at 450 KB and 12 s at 900 KB, past the hook's 5 s timeout; a `((` that opens two nested subshells is read as arithmetic; zsh's `noglob` and `repeat` prefixes and `&!` without a space before the next command are not read; and where the guard reads text as commands that a shell reads as data, a quote that opens and closes again there can still hide a command in between. It is a guardrail, not a sandbox: `eval`, `xargs`, `nix shell -c`, `$(command -v darwin-rebuild)`, `function f { ...; }` and running `activate` directly still pass; `tests/claude_hooks_test.sh` covers each case, and `tests/autoupdate_test.sh` cases 31 and 32 check that both aliases wait for the lock |
